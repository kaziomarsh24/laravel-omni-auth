## Architectural Highlights

<CardGrid>
  <Card title="Dual-Mode Token Engine" icon="padlock">
    Native support for two distinct client models from the same endpoints. Web SPAs receive hardened SameSite HttpOnly cookies with CSRF protection; mobile clients receive short-lived Bearer tokens and sliding refresh tokens.
  </Card>
  <Card title="Multi-Device Tracking & Revocation" icon="laptop">
    Every authenticated session records device fingerprint, OS, browser, IP address, and FCM push notification tokens. Users can inspect active devices and revoke suspect sessions remotely.
  </Card>
  <Card title="Two-Factor Authentication (TOTP)" icon="approve-check-circle">
    RFC 6238 compliant time-based one-time passwords with encrypted secrets at rest, cryptographically hashed recovery codes, and brute-force lockouts.
  </Card>
  <Card title="Unified Social Authentication" icon="puzzle">
    Supports traditional OAuth 2.0 redirect flows for web browsers alongside direct native ID token verification for Google and Apple (with live RS256 JWKS validation and strict cache management).
  </Card>
  <Card title="Account Pre-Hijacking Defense" icon="warning">
    Protects user accounts against unverified credential takeover. Pre-existing unverified password registrations linked via verified social providers automatically invalidate prior passwords and revoke stale sessions.
  </Card>
  <Card title="29 Ready-to-Use Endpoints" icon="rocket">
    Complete authentication surface covering registration, credential login, passwordless magic links, OTP password resets, device auditing, 2FA management, email verification, and self-service account deletion.
  </Card>
</CardGrid>

## Verified Test Coverage Matrix

Every release of Laravel OmniAuth is verified by an exhaustive automated test suite comprising **94 tests** and **514 assertions** spanning 10 architectural domains. The package has undergone two consecutive rounds of whitebox penetration auditing to ensure full resistance against credential stuffing, token replay, algorithm confusion, and session hijacking.

| Test Domain | Target Scenarios Verified | Tests / Assertions | Status |
| :--- | :--- | :---: | :---: |
| **Dual-Mode Delivery** | Web SameSite HttpOnly cookies vs Mobile Bearer tokens, token abilities isolation, dual-client header detection | 14 tests (78 assertions) | `Passed` |
| **Token Rotation & Replay** | Sliding refresh token rotation, replay attack detection, compromised family session invalidation | 6 tests (32 assertions) | `Passed` |
| **Two-Factor Auth (TOTP)** | RFC 6238 time drift (±1 window), encrypted secrets at rest, hashed recovery codes, brute-force lockout | 8 tests (54 assertions) | `Passed` |
| **Unified Social Login** | OAuth 2.0 CSRF state validation, Google/Apple native token exchange, RS256 JWKS caching & validation | 6 tests (42 assertions) | `Passed` |
| **Pre-Hijacking Defense** | Linking verified social account to unverified password account, auto-invalidation of prior credentials | 4 tests (24 assertions) | `Passed` |
| **Multi-Device Tracking** | Device fingerprinting (OS, browser, IP), FCM & Expo push token syncing, remote session termination | 8 tests (46 assertions) | `Passed` |
| **Registration & Hydration** | Dynamic field persistence, mass-assignment guards, case variants, default role assignment | 12 tests (68 assertions) | `Passed` |
| **Passwordless & GDPR** | Cryptographic 6-digit OTPs, signed magic links with host validation, full GDPR account cleanup | 7 tests (38 assertions) | `Passed` |
| **Penetration Security Audits** | Timing attacks, token confusion (HS256 vs RS256), Origin header spoofing, CSRF enforcement, URL tricks | 29 tests (132 assertions) | `Passed` |
