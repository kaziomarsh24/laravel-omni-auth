OmniAuth tracks every authenticated session as an active device record. Users can view every browser and mobile device logged into their account, inspect IP addresses and activity timestamps, and remotely log out suspicious sessions.

---

## Device Registration Lifecycle

Whenever an authentication event occurs (login, registration, social exchange, or magic link verification), OmniAuth extracts device details from the request:
- Client IP address (`request()->ip()`)
- Client platform (`ios`, `android`, `web`, `macos`, `windows`, `linux`)
- Browser or client application runtime
- Unique device identifier (`X-Device-Id` header or client-supplied UUID)
- Push notification token (optional Firebase Cloud Messaging token)

---

## Device Endpoints

### 1. List Active Devices

Retrieve all devices currently authenticated to the user's account (see [`GET /api/auth/devices`](/laravel-omni-auth/reference/api-reference/#get-apiauthdevices)):

```http
GET /api/auth/devices
Authorization: Bearer <access_token>
```

Response:
```json
{
  "ok": true,
  "data": {
    "devices": [
      {
        "id": 1,
        "device_id": "iphone-uuid-1234",
        "device_name": "iPhone 15 Pro",
        "platform": "ios",
        "browser": "OmniApp/1.0.0",
        "ip_address": "192.168.1.50",
        "is_current": true,
        "last_active_at": "2026-11-04T12:00:00Z"
      },
      {
        "id": 2,
        "device_id": "chrome-mac-uuid",
        "device_name": "Chrome on macOS",
        "platform": "web",
        "browser": "Chrome 128.0",
        "ip_address": "203.0.113.10",
        "is_current": false,
        "last_active_at": "2026-11-03T18:30:00Z"
      }
    ]
  }
}
```

The `is_current` boolean indicates whether that entry matches the token or device making the request.

---

### 2. Revoke a Specific Device

Revokes a remote device session by ID (see [`DELETE /api/auth/devices/{id}`](/laravel-omni-auth/reference/api-reference/#delete-apiauthdevicesid)):

```http
DELETE /api/auth/devices/2
Authorization: Bearer <access_token>
```

Response:
```json
{
  "ok": true,
  "message": "Device session successfully revoked."
}
```

When a device is revoked:
1. Its tracked `auth_devices` record is deleted.
2. The bound sliding refresh token is permanently deleted from Sanctum storage.
3. If that remote device subsequently attempts to call `/api/auth/refresh`, it receives HTTP 401 and is forced to log in again.

---

### 3. Revoke All Other Devices

Logs out every session across all browsers and devices except the one currently making the request (see [`POST /api/auth/devices/logout-others`](/laravel-omni-auth/reference/api-reference/#post-apiauthdeviceslogout-others)):

```http
POST /api/auth/devices/logout-others
Authorization: Bearer <access_token>
```

Response:
```json
{
  "ok": true,
  "message": "Successfully terminated 2 other device sessions.",
  "data": {
    "revoked_count": 2
  }
}
```

### 4. Update Push Notification Token (FCM / APNS / Expo)

Mobile clients can synchronize their device push tokens without re-authenticating (see [`POST /api/auth/devices/fcm`](/laravel-omni-auth/reference/api-reference/#post-apiauthdevicesfcm)). OmniAuth accepts push tokens via multiple formats to support Firebase Cloud Messaging, Apple APNs, and Expo Push:

<Tabs>
  <TabItem label="Firebase FCM Payload">

```http
POST /api/auth/devices/fcm
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "fcm_token": "fcm_token_sample_abc123..."
}
```

  </TabItem>
  <TabItem label="Expo / React Native Payload">

```http
POST /api/auth/devices/fcm
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "push_token": "ExponentPushToken[xxxxxxxxxxxxxxxxxxxxxx]"
}
```

  </TabItem>
  <TabItem label="Silent HTTP Header (Zero-Endpoint)">

Include the token on any authenticated request (e.g. `/api/auth/login`, `/api/auth/refresh`) without calling a separate endpoint:

```http
POST /api/auth/login
X-Push-Token: ExponentPushToken[xxxxxxxxxxxxxxxxxxxxxx]
Content-Type: application/json
```

  </TabItem>
</Tabs>

Response:
```json
{
  "ok": true,
  "message": "FCM token updated successfully.",
  "data": {
    "device": {
      "id": 1,
      "device_id": "iphone-uuid-1234",
      "fcm_token": "fcm_token_sample_abc123..."
    }
  }
}
```

:::tip[Universal Push Token Support (FCM & Expo APNs)]
OmniAuth natively supports both Firebase Cloud Messaging (FCM) and Expo / Apple Push Notification service (APNs) tokens out of the box. You can supply your push token using any of the following 4 methods:

1. **Request Body:** `push_token: "..."` (Expo / React Native convention)
2. **Request Body:** `fcm_token: "..."` (Firebase Cloud Messaging convention)
3. **HTTP Header:** `X-Push-Token: ...`
4. **HTTP Header:** `X-FCM-Token: ...`

**Zero-Endpoint Synchronous Tracking:** Mobile clients can include `X-Push-Token: ...` or `push_token` directly in `/api/auth/login`, `/api/auth/register`, or `/api/auth/refresh`. OmniAuth will silently bind the push token to the device record during authentication without requiring an extra API call!
:::
