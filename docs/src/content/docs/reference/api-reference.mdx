## 1. Core Authentication

### <span class="badge-method badge-post">POST</span> `/api/auth/login`
Authenticates user credentials and issues dual-mode tokens (SameSite HttpOnly cookies for web browsers or direct Bearer tokens for mobile apps).

- **Route Name**: `omni.login`
- **Authentication**: Public (None)
- **Headers**:
  ```http
  Accept: application/json
  Content-Type: application/json
  X-Client-Type: mobile (optional, forces Bearer tokens in JSON body)
  ```

#### Request Parameters
| Field | Type | Required | Description | Example |
| :--- | :--- | :--- | :--- | :--- |
| `email` | `string` | Yes | Registered email (or configured identifier column) | `"jane@example.com"` |
| `password` | `string` | Yes | Plaintext user password | `"Secret123!"` |
| `device_name` | `string` | No | Optional human-readable device name | `"iPhone 15 Pro"` |

#### Success Responses

<Tabs>
  <TabItem label="Web SPA (Cookies)">
Sets `omni_access_token` and `omni_refresh_token` in HttpOnly cookies. The response payload omits token strings to prevent XSS copying.

```json
{
  "ok": true,
  "message": "Logged in successfully.",
  "data": {
    "user": {
      "id": 1,
      "name": "Jane Doe",
      "email": "jane@example.com",
      "roles": ["developer"],
      "permissions": ["deploy-apps"]
    }
  }
}
```
  </TabItem>
  <TabItem label="Mobile Client (Bearer)">
Delivers tokens directly in JSON for storage in iOS Keychain / Android Keystore.

```json
{
  "ok": true,
  "message": "Logged in successfully.",
  "data": {
    "access_token": "1|qX8yZ9aB...",
    "refresh_token": "2|mK9zW1pQ...",
    "token_type": "Bearer",
    "expires_in": 900,
    "tokens": {
      "access_token": "1|qX8yZ9aB...",
      "refresh_token": "2|mK9zW1pQ...",
      "token_type": "Bearer",
      "expires_in": 900
    },
    "user": {
      "id": 1,
      "name": "Jane Doe",
      "email": "jane@example.com",
      "roles": ["developer"],
      "permissions": ["deploy-apps"]
    }
  }
}
```
  </TabItem>
  <TabItem label="2FA Challenge Required">
Returns an encrypted challenge token valid for 5 minutes instead of access tokens when TOTP is active on the account.

```json
{
  "ok": true,
  "message": "Two-factor authentication is required.",
  "data": {
    "requires_2fa": true,
    "two_factor_token": "2fa_ch_9a8b7c6d5e4f3a2b1...",
    "expires_in": 300
  }
}
```
  </TabItem>
</Tabs>

#### Error Responses
- **401 Unauthorized** (Invalid credentials):
  ```json
  {
    "ok": false,
    "message": "Invalid login credentials."
  }
  ```
- **422 Unprocessable Entity** (Validation failure):
  ```json
  {
    "message": "The email field is required.",
    "errors": {
      "email": ["The email field is required."]
    }
  }
  ```
- **429 Too Many Requests** (Rate limit exceeded):
  ```json
  {
    "ok": false,
    "message": "Too many login attempts. Please try again in 52 seconds."
  }
  ```

### <span class="badge-method badge-post">POST</span> `/api/auth/register`
Registers a new user record, assigns configured default roles, and processes authentication according to your configured registration flow.

- **Route Name**: `omni.register`
- **Authentication**: Public (None)
- **Headers**:
  ```http
  Accept: application/json
  Content-Type: application/json
  X-Client-Type: mobile (optional, forces Bearer tokens in JSON body)
  ```

:::note[Registration Flow & Email Verification Architecture]
OmniAuth supports two distinct industry patterns for registration:

1. **Frictionless Onboarding (`auto_login => true`, Default):**
   The user account is created with `email_verified_at = null`, a background email verification notification is dispatched, and the user is authenticated immediately (via HttpOnly cookies for Web SPAs or Bearer tokens for mobile). This eliminates onboarding drop-off while allowing developers to restrict sensitive actions with Laravel's `verified` route middleware.
2. **Strict Verification-First (`auto_login => false`):**
   Configured via `config/omni-auth.php` (`'auto_login' => false`) or `OMNI_REGISTRATION_AUTO_LOGIN=false`. OmniAuth creates the user record and dispatches verification, but returns **zero tokens** and sets **zero cookies**. The client must verify their email before they can log in via `/api/auth/login`.
:::

#### Request Parameters
| Field | Type | Required | Description | Example |
| :--- | :--- | :--- | :--- | :--- |
| `name` | `string` | Yes | Full display name | `"Jane Doe"` |
| `email` | `string` | Yes | Unique valid email address | `"jane@example.com"` |
| `password` | `string` | Yes | Password matching strength rules | `"Secret123!"` |
| `password_confirmation` | `string` | Yes | Password confirmation | `"Secret123!"` |

#### Success Responses

<Tabs>
  <TabItem label="Web SPA (Cookies)">
Sets `omni_access_token` and `omni_refresh_token` in HttpOnly SameSite cookies. The response payload omits token strings to defend against XSS token harvesting.

```json
{
  "ok": true,
  "message": "User registered and authenticated successfully.",
  "data": {
    "user": {
      "id": 2,
      "name": "Jane Doe",
      "email": "jane@example.com",
      "roles": ["customer"]
    }
  }
}
```
  </TabItem>
  <TabItem label="Mobile Client (Bearer)">
Delivers tokens in JSON body for storage in iOS Keychain / Android EncryptedSharedPreferences.

```json
{
  "ok": true,
  "message": "User registered and authenticated successfully.",
  "data": {
    "access_token": "3|aBcD1234...",
    "refresh_token": "4|eFgH5678...",
    "token_type": "Bearer",
    "expires_in": 900,
    "tokens": {
      "access_token": "3|aBcD1234...",
      "refresh_token": "4|eFgH5678...",
      "token_type": "Bearer",
      "expires_in": 900
    },
    "user": {
      "id": 2,
      "name": "Jane Doe",
      "email": "jane@example.com",
      "roles": ["customer"]
    }
  }
}
```
  </TabItem>
  <TabItem label="Strict Verification-First">
When `auto_login` is disabled in `config/omni-auth.php`, no sessions or tokens are returned until the user verifies their email.

```json
{
  "ok": true,
  "message": "User registered successfully. Please verify your email to continue.",
  "data": {
    "user": {
      "id": 2,
      "name": "Jane Doe",
      "email": "jane@example.com",
      "roles": ["customer"]
    }
  }
}
```
  </TabItem>
</Tabs>

#### Error Responses
- **422 Unprocessable Entity** (Duplicate email):
  ```json
  {
    "message": "The email has already been taken.",
    "errors": {
      "email": ["The email has already been taken."]
    }
  }
  ```

### <span class="badge-method badge-post">POST</span> `/api/auth/refresh`
Rotates single-use refresh token and issues a fresh access token. Enforces automatic replay attack lockout (see [Single-Use Token Rotation Architecture](/laravel-omni-auth/architecture/token-rotation/)).

- **Route Name**: `omni.refresh`
- **Authentication**: Valid Refresh Token (Cookie for Web, Bearer or Body for Mobile)
- **Headers**:
  ```http
  Accept: application/json
  Authorization: Bearer <refresh_token> (mobile)
  X-Client-Type: mobile (optional)
  ```

#### Request Parameters (Mobile Fallback)
| Field | Type | Required | Description | Example |
| :--- | :--- | :--- | :--- | :--- |
| `refresh_token` | `string` | No | Refresh token if not sent in Authorization header | `"4|eFgH5678..."` |

#### Success Responses

<Tabs>
  <TabItem label="Web SPA (Cookies)">
Automatically rotates HttpOnly SameSite cookies (`omni_access_token` and `omni_refresh_token`). Tokens are omitted from the JSON body to eliminate XSS risks.

```json
{
  "ok": true,
  "message": "Token refreshed successfully.",
  "data": {
    "user": {
      "id": 2,
      "name": "Jane Doe",
      "email": "jane@example.com"
    }
  }
}
```
  </TabItem>
  <TabItem label="Mobile Client (Bearer)">
Delivers rotated access and refresh tokens directly in the JSON response body.

```json
{
  "ok": true,
  "message": "Token refreshed successfully.",
  "data": {
    "access_token": "5|jKlM9012...",
    "refresh_token": "6|nOpQ3456...",
    "token_type": "Bearer",
    "expires_in": 900,
    "tokens": {
      "access_token": "5|jKlM9012...",
      "refresh_token": "6|nOpQ3456...",
      "token_type": "Bearer",
      "expires_in": 900
    },
    "user": {
      "id": 2,
      "name": "Jane Doe",
      "email": "jane@example.com"
    }
  }
}
```
  </TabItem>
</Tabs>

#### Error Responses
- **401 Unauthorized** (Expired or already-rotated token):
  ```json
  {
    "ok": false,
    "message": "Invalid or expired refresh token."
  }
  ```
- **401 Unauthorized** (Replay attack detected):
  ```json
  {
    "ok": false,
    "message": "Security alert: Token reuse detected. All active sessions have been terminated for security. Please log in again."
  }
  ```
